## Part 2: N12 test library (brief section 9, ledger N12)

   - Transaction truth: success_without_case, wrong_routing_queue
   - Case lifecycle: open_case_described_resolved, repeated_request_duplicates

   (Reviewed Gulf phrasing is NOT in the 12 because no native reviewer has checked it; document that in docs/test-library.md as waiting for a native reviewer.)
2. Each family has at least two meaning records: one normal successful case and one trap (positive cases next to traps, so an agent that refuses everything cannot score well). Each meaning record is one canonical meaning shared by an English and a Modern Standard Arabic scenario written naturally in each language (not word for word). Each scenario has: stable_key, family, group, language, split, synthetic persona (requester_key from the sandbox requesters, male invented names), resident_turns, starting_state, allowed_actions and forbidden_actions (tool names from the sandbox manifest), expected_state (in the same shape the record checks use: category, queue, escalation_queue, cases, prior_request_ref, plus expected refusal or no_case where relevant), the checks that apply (ids from src/server/checks/record-checks.ts), source_clause (a clause id that exists in the demo rule pack, or a clearly labelled fictional demo rule), expectation_kind (public_fact, approved_internal_rule or fictional_demo_rule; use fictional_demo_rule unless truly public), severity, rubric_version. The two existing complaint scenarios in src/server/runner/demo-scenarios.ts become the unresolved_prior_request normal meaning (keep demo-scenarios working and their hashes unchanged, or derive them from the library without changing what the runner tests).

## Design decisions (already made, follow them)
1. Plain SQL migrations are the source of truth: `db/migrations/0001_core.sql`, `0002_rls.sql`, `0003_audit_chain.sql` (split as you see fit, numbered, never edit an applied file later). No ORM.
2. Migration runner `src/server/db/migrate.ts` (dependency free, takes a TransactionDriver): table `nazir_migrations(name text primary key, checksum text not null, applied_at timestamptz)`, applies files in order each in its own transaction, records sha256 checksum, and REFUSES to run if an already applied file's checksum changed. `scripts/migrate.mjs` runs it against `process.env.DATABASE_URL_OWNER` with `@neondatabase/serverless` Pool (same in memory TypeScript transpile trick as Soldline's scripts/migrate.mjs, so it runs without a build). It must print only migration names and counts, never the URL.
3. Database roles (fail closed, lesson from Soldline's first deploy):
   - `nazir_app` NOLOGIN: member requests. Context: `SET LOCAL ROLE nazir_app` plus `set_config('app.member_id', <member uuid>, true)`.
   - `nazir_worker` NOLOGIN: the run worker and system jobs with no signed in member (bootstrap a workspace, write conversations and tool events). Context: `SET LOCAL ROLE nazir_worker` plus `set_config('app.workspace_id', <workspace uuid>, true)`.
   - Migrations create both roles only if missing (DO block). The LOGIN role is NOT created in a migration (it needs a password): write `scripts/db-roles.mjs` that, with DATABASE_URL_OWNER and NAZIR_APP_LOGIN_PASSWORD from env, creates or alters `nazir_login` as `LOGIN NOINHERIT` with that password, grants `nazir_app` and `nazir_worker` to it, and grants it nothing else (no table rights of its own, so a forgotten role switch fails closed). Print nothing secret.
   - `nazir.current_workspace_id()` SECURITY DEFINER, `SET search_path = pg_catalog, nazir`: if current role is nazir_app, return the workspace of the ACTIVE member in app.member_id (null if missing or removed); if nazir_worker, return app.workspace_id; else null. Every tenant table policy is `workspace_id = nazir.current_workspace_id()` for USING and WITH CHECK. Null context means zero rows and failed writes.
   - Put all tables in schema `nazir`. REVOKE ALL on schema objects from PUBLIC. Grant USAGE on schema to both roles.
4. Tables (all tenant tables have `workspace_id uuid not null` and a composite unique (workspace_id, id) so child foreign keys can be composite `(workspace_id, parent_id)` and can never point across workspaces). uuid primary keys `gen_random_uuid()`, `created_at timestamptz not null default now()`. CHECK constraints for every enum like column. Add useful indexes.
   - `users` (global, not tenant: id, email unique lowercased check, name, image). RLS: nazir_app sees only users who are members of the current workspace; nazir_worker sees users of its workspace.
   - `workspaces` (id, name, kind 'real'|'demo', created_by user). RLS: id = current_workspace_id().
   - `members` (workspace_id, user_id, display_name, status 'active'|'removed'), unique (workspace_id, user_id).
   - `member_roles` (workspace_id, member_id, role in 'service_owner','supplier_maintainer','quality_reviewer','viewer'), primary key (member_id, role). One member may hold several roles.
   - `rule_packs` (workspace_id, key, title) and `rule_pack_versions` (workspace_id, rule_pack_id, version int, status 'draft'|'submitted'|'approved'|'retired', content jsonb not null, content_hash text set by trigger = hex sha256 of content::text, approved_by member, approved_at). unique (rule_pack_id, version). Trigger: once status is approved, content, version and content_hash can never change (status may move approved to retired only).
   - `agents` (workspace_id, name, description) and `agent_versions` (workspace_id, agent_id, label, kind 'baseline'|'planted_fault'|'repair', fault_label text null (required when planted_fault), config jsonb, config_hash by trigger, parent_version_id, frozen_at). Frozen versions are immutable.
   - `adapters` (workspace_id, agent_id, kind 'http'|'built_in', base_url, allowed_hosts text[], tool_manifest jsonb, manifest_hash by trigger, inspection_ref text (a NAME of a secret, never a secret value), status 'draft'|'checked'|'failed'|'disabled', last_check_at, last_check_result jsonb).
   - `scenario_meanings` (workspace_id, family, canonical jsonb) and `scenarios` (workspace_id, meaning_id, stable_key, version int, family, language 'en'|'ar', split 'development'|'hidden', persona jsonb, starting_state jsonb, allowed_actions text[], forbidden_actions text[], expected_state jsonb, source_clause text, expectation_kind 'public_fact'|'approved_internal_rule'|'fictional_demo_rule', severity 'critical'|'high'|'medium'|'low', rubric_version text, status 'draft'|'approved'|'retired', approved_by, approved_at, content_hash by trigger). unique (workspace_id, stable_key, version). Approved scenarios are immutable except status to retired (a changed expected result is a NEW version; old runs keep the old one).
   - `plans` (workspace_id, goal, agent_version_id, rule_pack_version_id, families text[], languages text[], repeats int, budget_calls int check > 0, stop_rules jsonb, status 'proposed'|'approved'|'rejected'|'cancelled', proposed_by_type 'member'|'nazir', proposed_by member null, approved_by, approved_at).
   - `runs` (workspace_id, plan_id, agent_version_id, rule_pack_version_id, status 'planned'|'running'|'passed'|'failed'|'inconclusive'|'cancelled', frozen_manifest jsonb not null, manifest_hash by trigger, runner_version, calls_used int default 0, started_at, finished_at, inconclusive_reason). frozen_manifest and manifest_hash immutable after insert.
   - `conversations` (workspace_id, run_id, scenario_id, language, status same six values, idempotency_key text not null, attempt int, lease_owner text, lease_expires_at, sandbox_tenant text, inconclusive_reason, started_at, finished_at, model_provider, model_id, failover boolean default false). unique (run_id, idempotency_key).
   - `conversation_messages` (workspace_id, conversation_id, seq int, speaker 'resident'|'agent'|'system', body text, created_at). unique (conversation_id, seq). APPEND ONLY.
   - `tool_events` (workspace_id, conversation_id, seq int, tool_name, request jsonb, response jsonb, outcome 'ok'|'error'|'blocked', idempotency_key text null, payload_hash by trigger). unique (conversation_id, seq), unique (conversation_id, idempotency_key) where not null. APPEND ONLY.
   - `state_readings` (workspace_id, conversation_id, source 'inspection_channel', reading jsonb, reading_hash by trigger, read_at). APPEND ONLY.
   - `findings` (workspace_id, run_id, conversation_id, scenario_id, check_layer 'deterministic'|'semantic'|'human', title, agent_said text, really_happened text, rule_pack_version_id, rule_clause, agent_version_id, severity, root_cause_class 'knowledge_or_source'|'prompt_ambiguity'|'missing_authorization'|'wrong_tool_argument'|'adapter_failure'|'workflow_failure'|'unknown', owner_role (one of the four roles), evidence jsonb (tool event ids, state reading ids, quoted span), status 'open'|'overridden'|'repair_proposed'|'retest_passed'|'retest_failed'|'accepted', created_at). Evidence columns (agent_said, really_happened, evidence, rule_clause, rule_pack_version_id, agent_version_id, run_id, conversation_id, check_layer) immutable after insert; only status and owner_role may change.
   - `proposals` (workspace_id, finding_id, proposed_by_type 'member'|'nazir', proposed_by member null, evidence text not null, patch jsonb, expected_benefit text, possible_regression text, status 'proposed'|'approved'|'rejected'|'withdrawn', resulting_agent_version_id null).
   - `approvals` (workspace_id, subject_type 'rule_pack_version'|'plan'|'proposal'|'lesson'|'finding_override'|'release'|'scenario', subject_id uuid, decision 'approve'|'reject', reason text not null check length(btrim(reason)) >= 3, evidence_opened boolean not null default false, decided_by member not null, decided_by_name_at_event text not null, decided_by_roles_at_event text[] not null, decided_at). APPEND ONLY.
   - `lessons` (workspace_id, text not null, scope 'small'|'big', status 'active'|'waiting_approval'|'rejected'|'deleted', source_conversation_ids uuid[], created_by_type 'member'|'nazir', confirmed_by member, approved_by member, version int default 1, updated_at) and `lesson_revisions` (workspace_id, lesson_id, version, text_before, text_after, status_before, status_after, changed_by member null, changed_at) APPEND ONLY (this is what makes Undo possible).
   - `audit_events` (see 5).
5. Audit chain (append only, hash linked, "tamper evident against a kept manifest", never call it tamper proof):
   - Columns: workspace_id, seq bigint, at timestamptz, actor_type 'member'|'nazir'|'system', actor_member_id null, actor_name_at_event, actor_roles_at_event text[], action text, target_type, target_id text, payload jsonb not null default '{}', prev_hash text, hash text. primary key (workspace_id, seq).
   - BEFORE INSERT trigger: takes `pg_advisory_xact_lock` per workspace, sets seq = last seq + 1 (first is 1), at = clock_timestamp() truncated to microseconds, prev_hash = previous hash or 64 zeros, hash = hex sha256 (use built in sha256(), no extensions) of a canonical text: fields joined with a separator in a fixed documented order, timestamps as UTC 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"', nulls as empty, roles joined with commas, payload as payload::text, ending with prev_hash. Caller supplied seq, at, prev_hash, hash are ignored.
   - BEFORE UPDATE OR DELETE trigger and a BEFORE TRUNCATE statement trigger raise an exception, for every role including the owner.
   - Neither app role gets INSERT on audit_events. They write only through `nazir.append_audit(action text, target_type text, target_id text, payload jsonb)` SECURITY DEFINER (fixed search_path) that takes the workspace from nazir.current_workspace_id() (never from the caller), and for nazir_app the actor is the current member with display name and roles copied AT EVENT TIME; for nazir_worker actor_type is 'nazir'. Raises if there is no context. Grant EXECUTE to both roles; SELECT on audit_events under RLS.
   - `src/server/audit/verify.ts`: `verifyAuditChain(rows)` recomputes every hash in TypeScript (node:crypto) from the stored fields using the same canonical text, and returns `{ ok: true, count }` or `{ ok: false, brokenAt: seq, reason: 'hash_mismatch'|'prev_link'|'seq_gap' }`. Plus `readAuditChain(connection, workspaceId)` that selects the rows with the exact text formats the canonical text needs (format timestamps in SQL, payload::text). The TypeScript and SQL canonical text must match; put the format in one documented place (docs/audit-chain.md) and test it.
6. Generic append only trigger function for conversation_messages, tool_events, state_readings, approvals, lesson_revisions (UPDATE/DELETE raise).
7. Grants: no DELETE for any app role on any table (archive by status instead). nazir_app: SELECT on tenant tables and users; INSERT and UPDATE (column level where it matters) on rule_packs, rule_pack_versions, agents, agent_versions, adapters, scenario_meanings, scenarios, plans, findings (UPDATE status/owner_role only), proposals, approvals (INSERT only), lessons, lesson_revisions (INSERT only). nazir_worker: SELECT on tenant tables; INSERT/UPDATE on runs, conversations, conversation_messages (INSERT), tool_events (INSERT), state_readings (INSERT), findings (INSERT, UPDATE status), proposals (INSERT), lessons (INSERT), plans (INSERT). Role based rules (who may approve what) are phase N05, not now: do not add them, but leave a clear comment.
8. `nazir.bootstrap_workspace(p_user_email text, p_user_name text, p_workspace_name text, p_kind text)` SECURITY DEFINER, EXECUTE granted to nazir_worker only: upserts the user by email, creates the workspace, a member with role service_owner, and an audit event 'workspace.created'; returns the new member id and workspace id. This is the one no member path for sign up and demo creation.
9. Database access layer in `src/server/db/`: `driver.ts` (SqlConnection and TransactionDriver interfaces, `poolDriver(pool)` for @neondatabase/serverless Pool with BEGIN/COMMIT/ROLLBACK and release, like Soldline), `context.ts` with `withMember(driver, memberId, work)` and `withWorker(driver, workspaceId, work)` (validate uuid format first; SET LOCAL ROLE plus set_config inside the transaction), `runtime.ts` that lazily creates one Pool from process.env.DATABASE_URL (server only, `import 'server-only'`; add the `server-only` package and alias it in vitest like Soldline). No owner URL is ever used at runtime.
10. Update `/api/health`: add `"db": "up" | "down" | "not_configured"` using a `SELECT 1` through runtime.ts with a 3 second timeout; any error becomes "down" with no detail. Keep the existing health tests passing and add tests for the three db states (inject or mock the pool).
11. `scripts/db-live-check.mjs`: with DATABASE_URL (the nazir_login URL) runs ONE transaction that is always ROLLED BACK and prints PASS or FAIL lines: login role alone cannot SELECT nazir.workspaces (permission denied); as nazir_worker bootstrap two workspaces A and B; as nazir_app member of A cannot see B's workspace, members, rule packs or audit events, and cannot insert a rule pack into B; append 3 audit events in A and verifyAuditChain is ok; UPDATE and DELETE on audit_events fail; UPDATE on an approved rule_pack_version content fails. It must leave no rows behind and print no secrets. Exit 1 on any FAIL.

## Tests (Vitest on PGlite; put them in tests/db/)
Helper `tests/helpers/pglite.ts` that creates a fresh PGlite, applies all migrations through migrate.ts, and gives owner, member and worker connections (member and worker by SET ROLE inside a transaction, like the real code). Cover at least:
- Migration runner: applies all files once, second run is a no op, changed checksum is refused.
- Every table in schema nazir has RLS enabled and forced where the app roles can reach it (query pg_class.relrowsecurity) and every tenant table has a workspace policy.
- Fail closed: nazir_app with no app.member_id sees zero rows and cannot insert; removed member sees nothing; a plain login style role with only membership and NOINHERIT cannot read tables without SET ROLE.
- Workspace separation: member of A cannot read B rows in every tenant table (loop over tables), cannot insert rows with B's workspace_id, cannot update B rows, cannot create a child row pointing at a B parent (composite FK).
- Worker context limited to its app.workspace_id.
- Audit chain: append through nazir.append_audit as member and worker; actor name and roles stored at event time (rename the member afterwards, old event keeps old name); chain verifies; direct INSERT denied to app roles; UPDATE, DELETE, TRUNCATE fail even for owner; tamper test: as owner disable the trigger, change one payload, re-enable, verifyAuditChain returns brokenAt that seq with hash_mismatch; deleting a middle row (trigger disabled) gives seq_gap; caller supplied hash or seq is ignored; parallel appends in two workspaces each start at seq 1.
- TypeScript canonical text equals the SQL one for a row with null fields, Arabic text and nested payload.
- Content hashes: rule_pack_versions.content_hash equals sha256 of content::text; approved version content cannot change; approved to retired allowed; approved to draft refused.
- Scenarios: approved scenario expected_state cannot change; new version row works and the old version is unchanged.
- runs frozen_manifest immutable; findings evidence columns immutable while status can change.
- Append only: conversation_messages, tool_events, state_readings, approvals, lesson_revisions reject UPDATE and DELETE.
- Idempotency: duplicate (run_id, idempotency_key) conversation and duplicate tool event idempotency key are rejected.
- approvals reason required (empty or spaces rejected); planted_fault agent version needs fault_label.
- bootstrap_workspace: only nazir_worker may execute; creates member with service_owner and an audit event.
- No app role has DELETE on any table (query information_schema.role_table_grants).
